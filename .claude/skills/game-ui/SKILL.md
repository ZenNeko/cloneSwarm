# Game UI — Clone Swarm

Every menu screen is **generated by an Editor script**, rendered to PNG, critiqued, and
re-generated. Nothing is hand-authored in the scene. This doc is the map of that machine and
the failures it produces.

## What this project uses

**uGUI, not UI Toolkit.** `Canvas` + `CanvasScaler` + `GraphicRaycaster`, `Image` /
`RectTransform` / `TextMeshProUGUI`, `UnityEngine.UI.Button` / `Slider` / `TMP_Dropdown`.
All pre-existing game UI is uGUI; mixing the two would mean two layout systems in one screen.

**Reference resolution 1920×1080.** All builder constants are in those units.

| Piece | Where | Role |
|---|---|---|
| `P3RTheme.asset` | `Assets/ScriptableObjects/UI/` | the **only** source of colour, font, spacing, motion |
| `P3RBuilderKit.cs` | `Assets/Editor/` | shared helpers every builder uses via `using static` |
| `P3R<Screen>SceneBuilder.cs` | `Assets/Editor/` | one per screen — builds `Assets/GameScenes/Proto_<Screen>.unity` |
| `P3RScreenMigrator.cs` | `Assets/Editor/` | copies a proto panel into the real scene |
| `P3RScreenWirer.cs` | `Assets/Editor/` | reconnects controller references + button behaviour |
| `P3RScreensWindow.cs` | `Assets/Editor/` | `Window > Clone Swarm > P3R Screens` — drives all of it |
| `P3RSmokeTest.cs` | `Assets/Editor/` | enters real play mode and clicks through the menus |
| `P3RScreenshotTool.cs` | `Assets/Editor/` | renders every `Proto_*` scene to `/Screenshots` |

## The loop

```
สร้าง (build proto)  →  ย้ายลงซีน (migrate)  →  ต่อสาย (wire)  →  smoke test  →  render PNG  →  อ่านภาพ
```

One button does the first three: `Window > Clone Swarm > P3R Screens` → **สร้าง+ย้าย+ต่อสาย**.
Headless equivalent (Unity Editor must be **closed** — it holds `Temp/UnityLockfile`):

```bash
U="E:/Zenity Why not/Unity/6000.7.0a2/Editor/Unity.exe"
P="E:/Zenity Why not/cloneSwarm"
"$U" -quit -batchmode -nographics -projectPath "$P" \
     -executeMethod CloneSwarm.EditorTools.P3RCharacterSceneBuilder.Build -logFile "<ABS>/b.log"
"$U" -quit -batchmode -nographics -projectPath "$P" \
     -executeMethod CloneSwarm.EditorTools.P3RScreenMigrator.MigrateFromCommandLine \
     -screen "CHARACTER" -logFile "<ABS>/m.log"
"$U" -quit -batchmode -nographics -projectPath "$P" \
     -executeMethod CloneSwarm.EditorTools.P3RScreenWirer.WireMenuScene -confirm -logFile "<ABS>/w.log"
"$U" -batchmode -projectPath "$P" \
     -executeMethod CloneSwarm.EditorTools.P3RSmokeTest.Run -logFile "<ABS>/s.log"
```

Three flags are easy to get wrong and all three fail quietly:

- **`-logFile` must be an absolute path.** A bare filename resolves against the Git Bash install
  dir; Unity exits 127 with `Unable to open log file` — but the shell pipeline still reports 0.
- **Screenshots need a graphics device.** `-batchmode` alone is fine, `-nographics` is not.
  Builders and the migrator may use `-nographics`; `P3RScreenshotTool` may not.
- **The wirer needs `-confirm` in batchmode.** Without it it dry-runs. It once retargeted 170
  references and saved over the scene because batchmode skipped the confirm dialog.
- **`P3RSmokeTest.Run` must NOT get `-quit`** — it exits by itself when the test finishes.

## Where a thing belongs — prefab or builder

The project already draws this line and it is the right one:

| Thing | Form | Why |
|---|---|---|
| Screen chrome (top bar, tabs, panels, buttons) | **builder** | theme-driven, one instance, changes as a whole |
| Anything instantiated more than once at runtime (cards, rows, chips, tiles) | **prefab** | needs an Inspector, survives re-migration, one source for every copy |

Emit a prefab from the builder — do not hand-author it:

```csharp
private const string CardPrefab = PrefabDir + "/CharacterCard.prefab";

private static CharacterCardUI BuildCardPrefab()
{
    var rt = NewRect("CharacterCard", null);      // parent null = สร้างลอยไว้ก่อน
    ...
    return SavePrefab(rt.gameObject, CardPrefab).GetComponent<CharacterCardUI>();
}
```

Then put mock copies in the proto scene with `SpawnSample(prefab, parent, bind)` so the PNG shows
a populated screen. The wirer deletes every `Sample_*` when the panel lands in the real scene.

**Never hand-edit these prefabs — `SavePrefab` regenerates them on every build.** A guard now
refuses to overwrite a prefab whose bytes differ from what the builder last wrote
(hashes in `Assets/Prefab/UI/P3R/.p3r-prefab-hashes.txt`); batchmode logs an error and skips
the file unless you pass `-forceprefab`. It exists because two prefabs were hand-tuned and then
silently destroyed by a rebuild that happened to reproduce the previous commit byte-for-byte, so
git recorded no diff and there was nothing to recover. When you want a change to stick, put it in
the builder. Every builder must route through `P3RBuilderKit.SavePrefab` — a local copy of it
bypasses the guard, which is how `ResultPartyRow` stayed unprotected after the rest were fixed.

**Artwork images are `Color.white`, always.** An `Image`'s colour multiplies into the sprite, so
any tint means the art no longer matches what the artist drew and nobody can find where the shift
came from. Dim a locked card with an overlay on top, never by tinting its portrait.
`P3RBuilderKit.PortraitWithName` enforces this and lays out the shared **8:1** portrait box with
the name overlaid on its bottom-left — the ratio comes from the result screen's 470×58 box and is
the same in every row and card so one set of character art fits everywhere uncropped.

A controller's `cardTemplate` field must point at the **prefab asset**, not a scene object — a
scene reference is a `fileID` that changes every time the panel is re-migrated, and the template
gets destroyed along with the old panel.

## Lists, carousels, filmstrips

`CarouselBase<TData, TCard>` (`Assets/Script/UI/CarouselBase.cs`) holds everything: layout,
drag, wheel, snapping, data binding, the featured-image layer. A concrete list is three methods:

```csharp
public class CharacterCarousel : CarouselBase<CharacterData, CharacterCardUI>
{
    protected override void Bind(CharacterCardUI c, CharacterData d, Color sel, Color norm)
        => c.SetData(d, sel, norm);
    protected override void SetCardSelected(CharacterCardUI c, bool on) => c.SetSelected(on);
    protected override Sprite FeaturedSpriteOf(CharacterData d) => d != null ? d.portrait : null;
}
```

Two concrete subclasses exist because **Unity cannot attach an open generic MonoBehaviour to a
GameObject** — it needs a closed type. That is the only reason; there is no logic in them.

Configure it in the **builder**, never leave it to the controller's runtime `AddComponent`
fallback (that path uses every default and is how the layout silently stopped matching the design):

```csharp
var list = panel.gameObject.AddComponent<CharacterCarousel>();
list.axis      = CarouselAxis.Vertical;     // Horizontal for a filmstrip
list.align     = CarouselAlign.Start;       // Start = plain list · Center = locked-centre wheel
list.pitch     = CardH + CardGap;           // MUST equal card size along the axis + gap
list.centerScale = list.edgeScale = 1f;     // P3R cards are all one size
list.fadeByDistance = false;
panel.gameObject.AddComponent<RectMask2D>();  // or cards spill over neighbouring screens
```

The component must sit on a **parent of the card container**, not on the Canvas — uGUI drag and
scroll events only reach the object under the pointer and its ancestors.

`align` changes the meaning of scrolling, not just positions:
- `Center` — the selected item is always centred, scrolling wraps forever, **scrolling is selecting**.
- `Start` — items start at the panel edge and do not wrap, **scrolling and selecting are separate**
  (scroll to look, click to choose). This is what the P3R design actually specifies.

## Thai text

- Thai combining marks are zero-width. `characterSpacing > 0` detaches them from their
  consonants. **Thai must always be spacing 0.**
- Thai has no uppercase, so it reads lighter beside Latin ALL-CAPS. `P3RTheme.thaiFontScale`
  (1.08) compensates. `P3RMenuItem` deliberately does **not** apply it — `rowPitch` is a constant
  and 8% makes menu rows collide.
- Any label a script writes at runtime needs `P3RThaiTracking` on it — the builder's decision was
  made when the text was still the English placeholder. `Tools > Clone Swarm > Fix Thai Risk (ใส่ตัวเฝ้าระยะถ่าง)`
  attaches it to every label a project script holds.
- Fonts must be baked with `includeFontFeatures: true` or tone marks stack on top of vowels.
  `Tools > Clone Swarm > Fix Thai Fonts`.
- Sarabun has no `✓ ⚠ ✗`. Draw them as `Image` shapes.

## Verifying

Three kinds of verification catch three disjoint sets of bugs. A change is not done until all
three are green.

| Kind | Tool | Catches |
|---|---|---|
| Visual | `P3RScreenshotTool.CaptureAll` → read the PNG | wrong spacing, colour, hierarchy, overflow |
| Structural | YAML scan / `P3RScreenWirer.Report` | broken refs, `m_Script: {fileID: 0}`, duplicate panels |
| Behavioural | `P3RSmokeTest.Run` | dead buttons, wrong layout at runtime, missing singletons |

`P3RSmokeTest` asserts **layout and clicks**, not just structure — card count vs data count, cards
inside the mask, ordering along the axis, and a real `EventSystem.RaycastAll` at the card's screen
position followed by `ExecuteEvents.ExecuteHierarchy`. Add a check there whenever a UI bug reaches
the user; every check in it is there because something shipped broken.

## Compile-checking while the Editor is open

`Temp/UnityLockfile` blocks batchmode most of the time (the owner works with the Editor open).
Drive Roslyn with Unity's own build-graph response file instead:

```bash
RSP=$(ls -t Library/Bee/artifacts/*.dag/Assembly-CSharp.rsp | head -1)
sed -e 's#^-out:.*#-out:"<SCRATCH>/AC.dll"#' -e 's#^-refout:.*#-refout:"<SCRATCH>/AC.ref.dll"#' \
    "$RSP" > <SCRATCH>/AC.rsp
dotnet "E:/Zenity Why not/Unity/6000.7.0a2/Editor/Data/DotNetSdk/sdk/8.0.318/Roslyn/bincore/csc.dll" \
    "@<SCRATCH>/AC.rsp"
```

For `Assembly-CSharp-Editor.rsp`, also repoint its `-r:` for `Assembly-CSharp.ref.dll` at the
freshly built one, or it compiles against the Editor's stale DLL and reports phantom errors.
The `.dag` hash changes when Unity regenerates the build graph — glob for it, never hardcode.
The source list is only valid while no `.cs` file was added or deleted.

# Hard rules earned the expensive way

**`P3RBuilderKit.NewImage` sets `raycastTarget = false`.** Correct for the dozens of decorative
images per screen, fatal for anything clickable. A card whose every Graphic has it off looks
completely healthy — Button present, `interactable` ticked, listener attached — and never receives
a click, because the EventSystem does not know the pointer is over it. The Inspector shows
`Target Graphic: None` and `On Click () List is Empty`, and **both of those are normal** for a
button wired at runtime, so they point nowhere. Set `bg.raycastTarget = true` on anything
interactive. `CarouselBase.EnsureClickable` now turns it on and warns, but fix the template.

**A Button on a card must be `Transition.None`.** The card's background colour is owned by
`SetSelected()`. Leaving Color Tint on means two writers for one colour, and the selected card
flashes back to normal every time the pointer leaves it.

**Migration is destroy-and-recreate.** `P3RScreenMigrator` deletes the whole existing panel.
Anything hand-set in the scene is gone. Asset references are snapshotted and restored
(`SnapshotAssetData` / `RestoreAssetData`) because `CharacterSelectUI.characters` and
`LobbyUI.maps` exist nowhere else; scene references are the wirer's job. Never hand-edit a
migrated panel expecting it to survive.

**Never assume a panel is a direct child of the Canvas.** `P3RScreenWirer.EnsureHub` moves the
four tab screens under `P3R_Hub` after the first migration. A shallow name lookup then misses the
existing panel and creates a *second* one at the Canvas root — the old one keeps the real data and
stays the one the game uses, so every builder edit appears to do nothing, silently. Search the
whole subtree and put the replacement back at the same parent and sibling index.

**The wirer matches by controller type only.** Matching components by type alone once dragged
every `Button` in the scene onto one panel's first button and every TMP onto its first label —
170 references in one pass, saved to disk. Empty `GameObject` fields use an explicit name table
(`PanelFieldMap`), never a type guess.

**`viewCount` larger than the item count means duplicate cards.** One map produced four
`ARENA 01` cards stacked down the middle of the screen. Build `min(viewCount, ItemCount)` views.

**Panels holding a singleton must be left active.** `LevelUpUI` / `WinLoseUI` set `Instance` in
`Awake()`, and `Awake` does not run on an inactive GameObject. They hide themselves in
`Awake`/`Start`, so an active panel is not a visible panel.

**One MonoBehaviour class per file.** A scene only binds the script reference for the class whose
name matches the file name. `BuildStripSlot` living inside `BuildStripUI.cs` became
`m_Script: {fileID: 0}` on ten objects the moment the panel crossed scenes — invisible in the PNG,
invisible in the wiring report, only countable in the YAML.

**uGUI blends in linear space.** White at alpha `0.10` over `#0D1226` renders as `#5B5D61`, not
the `#252A3C` a CSS intuition predicts. Use `Over(top, under, a)` / `Lift(under, a)` from the kit
to pre-blend to an opaque colour instead of stacking low-alpha layers.

**Load the theme *after* `EditorSceneManager.NewScene`.** Loading before it leaves a fake-null
reference in batchmode: the scene builds to completion, exits 0, and has no fonts, colours, or
bars. `P3RBuilderKit.BeginScene` already orders it correctly — do not reorder.

**`using static P3RBuilderKit` makes `Mono()` ambiguous** with the .NET `Mono` namespace (CS0118).
The tracking helper is called `MonoStyle`.

**Do not invent data that has no source.** The map screen shows `—` for `ENEMY HP` because
`DifficultyTier` is a bare enum with no multiplier to read, and hides `LOCKED ×2` because there is
no map-unlock system. The loading bar is an indeterminate sweep because
`NetworkManager.SceneManager.LoadScene` reports events, not progress. Showing a plausible number
tells the player a system exists when it does not.
