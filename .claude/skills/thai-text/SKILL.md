# Thai text (Clone Swarm)

Thai breaks four assumptions that Latin-only UI code never tests: marks stack above and below the
consonant, they have **zero width**, there is **no letter case**, and **there are no spaces
between words**. Every bug below comes from one of those four.

## Symptom → cause

| What you see | Cause | Fix |
|---|---|---|
| `เพื่อ` renders as `เพือ` — marks collapse into one blob | `fontFeatureTable` empty; TMP does no mark-to-mark positioning on its own | `Tools > Clone Swarm > Fix Thai Fonts` |
| Same, but **only in a real build** | `m_ClearDynamicDataOnBuild` wipes the baked table | same tool — it turns that flag off |
| `เพื่อ` renders as `เพื ่อ` — marks drift off the consonant | letter-spacing applied to zero-width marks | never set `characterSpacing` directly — see below |
| Thai looks lighter/shorter beside English | Thai has no capitals, so ALL-CAPS Latin next to it reads taller | `P3RThaiTracking.thaiFontScale` (default `1.08`) |
| Menu rows collide after switching to Thai | that 8% applied where row pitch is a constant | `P3RMenuItem` opts out on purpose — leave it |
| Line breaks in the middle of a word | no spaces in Thai; TMP has no Thai dictionary | `Tools > Clone Swarm > Add Thai Word Break To Scenes` |
| `✓ ⚠ ✗ ★ ⚡` render as boxes | no font in the project has those code points | draw as `Image`, or import a symbol font as a second fallback |

## Never write `characterSpacing` directly

The design language calls for `.16–.30em` tracking on mono-style labels. That is correct for
Latin and destroys Thai, because TMP adds the gap after *every* glyph including the zero-width
marks that must sit on the previous consonant.

Two helpers own this decision. Use them instead:

| Situation | Use |
|---|---|
| Text set once, at build time | `P3RText.SetTracking(label, spacing)` / `SetTextAndTracking(label, text, spacing)` |
| Text a script rewrites at runtime | `P3RThaiTracking` component on the label |

`P3RTheme.thaiFontScale` is the project-wide default; `P3RThaiRiskAudit` copies it into each
component it attaches. Change the theme for a global adjustment, the component for one label.

The rule is **any Thai character at all → tracking 0**. Slightly stricter than necessary, chosen
because letter-spacing is not a Thai typographic convention anyway.

`P3RThaiTracking` exists because `P3RText` can only decide *when called* — the builder calls it
while the text is still an English placeholder, and whatever writes the translated string later
(`CharacterSelectUI`, `MapCardUI`, `TalentTileUI`, …) leaves the stale spacing behind. The
component moves the decision onto the label itself, so no future writer has to remember the rule.

**Every label a script writes at runtime needs it.** `Tools > Clone Swarm > Audit Thai Risk` lists
the ones missing it; `Fix Thai Risk (ใส่ตัวเฝ้าระยะถ่าง)` attaches them.

Also: `P3RText.TryUpperCase` returns whether it actually did anything. Thai has no uppercase, so
forcing ALL-CAPS silently loses the design's look when the language switches — check the return
value and compensate with weight or size rather than assuming it applied.

## Word breaking

ThaiTextCare (`com.phengine.thaitextcare`, a git package in `Packages/manifest.json`) provides
`ThaiTextNurse`, one component per `TMP_Text`, which inserts zero-width break opportunities using
a dictionary.

```
Assets/Plugins/ThaiTextCare/Resources/dictionary.txt   ← 76,314 words, tracked in git
```

That file is **generated by the plugin on first run** and is committed deliberately — without it a
fresh clone silently cannot break Thai lines until someone opens the Editor once.

`Add Thai Word Break To Scenes` only touches labels whose `textWrappingMode` is `Normal` — a label
set to `NoWrap` does not need it and gets skipped.

## Fonts

`Fix Thai Fonts` operates on **fonts the game actually uses** — anything that is a dependency of a
scene or prefab — deliberately not a hand-written list, so a newly used font is picked up next run
and nine unused weights do not bloat the repo's atlases.

Per font it bakes Latin + the whole Thai block + UI symbols into the character table with
`includeFontFeatures: true` (pulling the font's own GPOS data), turns off
`m_ClearDynamicDataOnBuild`, then applies a **per-font** `ThaiFontDoctor` asset. Per-font matters:
`ApplyModifications()` remembers the pairs it inserted so it can remove them on re-run, so one
shared doctor asset would delete another font's pairs. Re-running is safe and does not accumulate.

Adding a new font to the project: use it in a scene or prefab first, then run the tool.

## Putting strings in the String Table

The six ScriptableObject types (`WeaponData`, `AbilityData`, `CharacterData`, `MapData`,
`StatData`, `TalentData`) already use `LocalizedString` for display text. Table: `Content`,
locales `en` and `th-TH`.

**If you convert another `string` field to `LocalizedString`, harvest first.** Unity's serializer
drops the old value outright when the field type changes — 88 assets' worth of Thai descriptions
vanished-in-one-step is exactly the failure this guards against.

```
Tools > Clone Swarm > Localization > 1. Harvest ScriptableObject Text   ← run BEFORE changing the type
Tools > Clone Swarm > Localization > 2. Relink LocalizedString fields
```

Harvest is read-only on the source assets and idempotent — existing keys are skipped so it never
overwrites a human translation (use `1b.` only when you intend to overwrite). It routes a string
by its own characters: any Thai character → `th-TH`, otherwise → `en`. Mixed strings count as Thai
because the sentence structure is Thai, and the other column is left empty for a translator.

**English text sitting in the `th-TH` column is a row awaiting translation, not a decision.** Do
not "fix" it by copying it into `en` as though it were final.

## Checklist for a new Thai-bearing label

1. `P3RThaiTracking` on it if anything writes the text at runtime
2. `ThaiTextNurse` on it if it wraps
3. Its font baked by `Fix Thai Fonts`
4. Its string in the `Content` table, not a literal in code
5. No `✓ ⚠ ✗` in the string — use an `Image`
6. Render a screenshot and actually look at the marks; none of the above shows up in YAML
