# Unity Multi-Agent Loop

เป้าหมายที่ผู้ใช้สั่ง: **$ARGUMENTS**

คุณคือ **Architect / Orchestrator** — คุณ **ไม่เขียนโค้ด C# เอง** หน้าที่คือวางแผน ส่งงานให้ coder
แล้วตรวจผลลัพธ์ วนซ้ำจนคอมไพล์ผ่าน

**coder ปัจจุบันคือ Antigravity ซึ่งเป็น GUI ไม่มี CLI** → Phase 2 เป็น handoff ที่คุณต้องหยุดรอผู้ใช้
ไม่ใช่คำสั่งที่คุณรันเองได้ ดูรายละเอียดใน Phase 2

---

## กติกาสำคัญ (ห้ามฝ่าฝืน)

1. **ห้ามแก้ไฟล์ `.cs` ด้วยตัวเอง** — งานเขียนโค้ดเป็นของ Gemini ทั้งหมด
   (ยกเว้น Gemini ล้มเหลว 3 รอบติดที่ error เดิม แล้วผู้ใช้อนุญาต)
2. **จำกัดลูปไม่เกิน 5 รอบ** ครบแล้วยังไม่ผ่าน → หยุดและรายงาน
3. **อ่านไฟล์เท่าที่จำเป็น** — ห้าม glob ทั้ง `Assets/` เพราะกินโควตา Pro เปล่าๆ
   ใช้ Grep หา symbol / class ที่เกี่ยวข้องก่อน แล้วค่อย Read เฉพาะไฟล์นั้น
4. ห้ามแตะ `Library/`, `Temp/`, `obj/`, `Build/`, `scratch/`
5. กฎเฉพาะโปรเจกต์อยู่ใน `CLAUDE.md` (server-authoritative, `NetworkedVFXPool`, `SoundManager`,
   ต้องลงทะเบียน prefab ใน `DefaultNetworkPrefabs.asset`) — **ต้องคัดลอกกฎที่เกี่ยวข้องลงในแผน**
   เพราะ Gemini อ่าน `CLAUDE.md` ไม่เป็น มันเห็นแค่ `docs/implementation_plan.md`

## Phase 0 — เช็คสภาพแวดล้อม (ทำครั้งเดียวตอนเริ่ม)

```powershell
powershell -ExecutionPolicy Bypass -File scripts/unity-check.ps1 -DryRun
```

เช็คว่าเจอ Unity.exe และโปรเจกต์ไม่ถูก Editor ล็อกอยู่ (ใช้เวลาไม่ถึงวินาที ไม่ได้รัน Unity จริง)
ถ้า exit 2 → แก้ให้จบก่อนค่อยเริ่มลูป อย่าเสียเวลาให้ Gemini เขียนโค้ดแล้วมาตรวจไม่ได้

```bash
git -C "$PWD" status --porcelain
```

ถ้ามีไฟล์ค้าง uncommitted จำนวนมาก → เตือนผู้ใช้ก่อนว่าจะปนกับงานของ Gemini

ถามผู้ใช้ให้แน่ใจว่า **Antigravity เปิดโฟลเดอร์นี้อยู่** ก่อนเริ่ม Phase 1 — จะได้ไม่ต้องรอตอน handoff

## Phase 1 — สำรวจและวางแผน

1. อ่าน `docs/implementation_plan.md` ถ้ามีอยู่แล้ว (อาจเป็นงานค้าง — ถ้า task ยังไม่ติ๊กครบ ให้ถามผู้ใช้ว่าจะทำต่อหรือเริ่มใหม่)
2. ใช้ Grep/Glob หาไฟล์ที่เกี่ยวกับเป้าหมาย — เจาะจง ไม่เหวี่ยงแห
3. **เขียนทับ** `docs/implementation_plan.md` ด้วยโครงนี้:

```markdown
# Implementation Plan
> Generated by Claude (Architect) — <วันเวลา>
> Goal: <เป้าหมาย>
> Round: 1

## Context
- ไฟล์ที่เกี่ยวข้อง: <path list พร้อมเหตุผลสั้นๆ>
- โครงสร้างที่มีอยู่แล้วและต้องใช้ซ้ำ: <base class / manager / enum ที่ต้องต่อยอด>

## Project Rules (ห้ามละเมิด)
- damage ต้องผ่าน `PlayerWeaponManager.<Action>ServerRpc` เท่านั้น ห้ามเรียก `Enemy.EnemyTakeDamage` จาก client
- VFX ใช้ `NetworkedVFXPool.Instance.PlayByType(VFXType.X, pos)` เท่านั้น ห้าม `Instantiate`
- SFX ใช้ `SoundManager.Instance.PlaySfx*` เท่านั้น
- <กฎอื่นที่เกี่ยวกับงานนี้ คัดจาก CLAUDE.md>

## Tasks
- [ ] T1: <คำสั่งชัดเจนระดับที่ Gemini ทำได้ทันที>
  - File: `Assets/Script/.../Xxx.cs`  (CREATE / MODIFY)
  - Signature: `protected override void OnFire(WeaponLevelData ld)`
  - Expected: <ผลลัพธ์ที่ต้องได้>
- [ ] T2: ...

## Acceptance Criteria
- คอมไพล์ผ่าน 0 error
- <เงื่อนไขเฉพาะงานนี้>

## Do NOT
- ห้ามแก้ไฟล์ที่ไม่ได้ระบุใน Tasks
- ห้ามเปลี่ยน signature ของ public API เดิม
- ห้ามแตะ `Library/`, `Temp/`, `obj/`, `scratch/`
- ห้ามรันคำสั่ง shell — Claude เป็นคนรัน unity-check เอง
```

**แผนต้องละเอียดพอที่ Gemini ทำได้โดยไม่ต้องเดา** — ระบุชื่อไฟล์ ชื่อคลาส ชื่อเมธอด และ signature ให้ครบ
ถ้าต้องสร้าง prefab / ScriptableObject ให้ระบุว่าเป็นงานมือของผู้ใช้ใน Editor (Gemini ทำไม่ได้) แล้วเก็บไว้รายงานตอนจบ

## Phase 2 — ส่งงานให้ coder

**โหมดปัจจุบัน: B — Antigravity** (ตัดสินใจ 2026-07-28)
เหตุผล: Gemini CLI ใช้โควตา Google AI Pro ไม่ได้แล้ว (Google ปิด OAuth สำหรับบัญชีบุคคล)
เหลือ free tier 5 req/นาที ซึ่งช้าเกินใช้งาน ส่วน Antigravity เข้าถึงโควตา AI Pro ได้เต็ม

Antigravity **ไม่มี CLI** มีแต่ GUI → คุณสั่งเองไม่ได้ ต้อง handoff ให้ผู้ใช้

### ขั้นตอน

**1. บันทึก baseline ก่อนส่งงาน** (ไว้เทียบว่าอะไรเปลี่ยนจริง)

```bash
git -C "$PWD" rev-parse HEAD && git -C "$PWD" status --porcelain
```

**2. เขียนข้อความ handoff ลงไฟล์ `docs/handoff.md`** — **อย่าพิมพ์ข้อความไทยยาวๆ ลง terminal**

terminal บางตัว (โดยเฉพาะ integrated terminal ของ IDE) วาดภาษาไทยเพี้ยนเพราะ combining marks
กว้าง 0 คอลัมน์ ทำให้ตัวอักษรทับกันจนก๊อปไม่ได้ → ให้เขียนลงไฟล์แล้วบอกผู้ใช้ให้เปิดในตัว editor

เนื้อหาในไฟล์ (เขียนทับทุกรอบ):

```markdown
# Handoff → Antigravity  (Round <n>)

ก๊อปข้อความข้างล่างนี้ไปวางใน Antigravity:

---
อ่าน AGENTS.md แล้วอ่าน docs/implementation_plan.md จากนั้นลงมือทำทุก Task ที่ยังเป็น [ ] แก้เฉพาะไฟล์ที่แผนระบุ ห้ามรัน build หรือ unity-check เสร็จแต่ละ task ให้ติ๊ก [x] และสรุปไฟล์ที่แก้ไว้ท้ายไฟล์แผนใต้ ## Changed Files
---

รอบนี้ให้ทำ: <สรุปสั้นๆ ว่า task ไหนบ้าง>
เสร็จแล้วกลับมาบอกว่า "เสร็จ"
```

แล้วในแชตพิมพ์สั้นๆ เป็นอังกฤษ/ตัวเลขว่า `handoff written -> docs/handoff.md (Round n, N tasks)`

**3. จบเทิร์น รอผู้ใช้**
อย่าเดาว่าเขาทำเสร็จแล้ว อย่ารัน Phase 3 ต่อทันที **อย่าลงมือเขียนโค้ดเอง**
รอจนผู้ใช้บอกว่าเสร็จ (เช่น "เสร็จแล้ว" / "done" / "รันต่อ")

**4. พอผู้ใช้กลับมา — ตรวจก่อนว่ามีอะไรเปลี่ยนจริง**

```bash
git -C "$PWD" diff --stat
```

- **ไม่มีอะไรเปลี่ยน** → อย่าวนลูป ถามผู้ใช้ว่า Antigravity รันไม่สำเร็จหรือยังไม่ได้กด
- **แก้ไฟล์นอกแผน** → บันทึกไว้ แจ้งตอนจบ **อย่า revert เองโดยไม่ถาม**
- มีคำถามใต้ `## Questions` ในไฟล์แผน → ตอบให้ครบก่อนสั่งรอบต่อไป

## Phase 3 — ตรวจสอบด้วย Unity CLI

```powershell
powershell -ExecutionPolicy Bypass -File scripts/unity-check.ps1
```

ตั้ง timeout 600000 ms — วัดจริงบนโปรเจกต์นี้แล้ว **warm cache = ~41 วินาที**

> ถ้า `Library/` ว่าง (clone ใหม่ / เปลี่ยนเวอร์ชัน Editor / ลบ Library) รอบแรกกิน **~62 นาที**
> เกิน timeout แน่นอน → ให้ผู้ใช้รัน `scripts/unity-check.ps1` ด้วยตัวเองครั้งหนึ่งก่อนเริ่มลูป
> อย่าเปิดลูปทับ cold cache

**exit code**
- `0` = คอมไพล์สะอาด → ไป Phase 5
- `1` = มี error → อ่าน `scratch/errors.txt` (ไฟล์นี้มีแต่บรรทัด error ล้วน ประหยัด context กว่าอ่าน `build.log` ทั้งไฟล์)
- `2` = **Unity Editor เปิดโปรเจกต์ค้างอยู่ หรือหา Unity.exe ไม่เจอ** → ไม่ใช่ปัญหาโค้ด
  ให้บอกผู้ใช้ปิด Editor แล้วสั่งใหม่ **ห้ามนับเป็นรอบล้มเหลว**

## Phase 4 — วิเคราะห์แล้ววนกลับ

อย่าส่ง log ดิบกลับไปให้ Gemini — วิเคราะห์ก่อน:
- error นี้มาจาก task ไหน
- สาเหตุราก: พิมพ์ผิด / ขาด `using` / signature ไม่ตรง / เรียก API ที่ไม่มีจริง / ละเมิดกฎโปรเจกต์
- ต้องแก้ไฟล์ไหน บรรทัดประมาณไหน

แล้ว **ต่อท้าย** `docs/implementation_plan.md`:

```markdown
## Fix Round <n>
- [ ] F1: <คำสั่งแก้ที่เจาะจง>
  - File: `...cs` line ~<n>
  - Error: `CS0246: The type or namespace name 'Xxx' could not be found`
  - Root cause: <วิเคราะห์ของคุณ>
  - Fix: <ต้องเขียนอะไรแทน>
```

วนกลับ **Phase 2** (นับรอบเพิ่ม 1)

**เงื่อนไขหยุดก่อนครบ 5 รอบ:**
- error เดิมเป๊ะๆ ซ้ำ 3 รอบติด → Gemini ติดลูป หยุด ถามผู้ใช้ว่าจะให้คุณแก้เองไหม
- จำนวน error เพิ่มขึ้นทุกรอบ → Gemini กำลังทำพัง เสนอ `git checkout` ไฟล์ที่เสีย

ครบ 5 รอบยังไม่ผ่าน → หยุด รายงาน error ที่เหลือ + สมมติฐานว่าติดตรงไหน + ขอคำตัดสิน

## Phase 5 — ปิดงาน

รายงานสั้นๆ:
- ไฟล์ที่ถูกแก้ (`git diff --stat`)
- จำนวนรอบที่ใช้
- **งานมือที่เหลือใน Unity Editor** — สร้าง/ผูก prefab, สร้าง ScriptableObject, เพิ่มลง
  `Assets/DefaultNetworkPrefabs.asset`, ลาก reference ใน Inspector
- สิ่งที่ควรทดสอบด้วยมือ (โดยเฉพาะพฤติกรรม multiplayer ที่ compile check จับไม่ได้)

ปิดท้ายด้วยการถามว่าจะให้รัน `scripts/unity-check.ps1 -Audit` (ProjectAutomatedAuditor) ต่อไหม
