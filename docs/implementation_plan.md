## Context

**รอบนี้ต่างจาก Round 1-6 ทั้งหมด** — 6 รอบที่ผ่านมาคือแก้บั๊กจาก audit ซึ่ง**เก็บไปเกือบหมดแล้ว**
รอบนี้เป็น**ฟีเจอร์ที่ผู้ใช้ขอ** หลังเล่นเทสต์จริง

ของหลักคือ **เลขดาเมจลอยขึ้นตอนตี** ซึ่งปลดล็อกสองข้อที่ค้างในเทสต์ไปพร้อมกัน:
- *"ยิงจนคริต → เห็น CritHitEffect"* — ไม่ได้สังเกต เพราะแยกไม่ออกด้วยตา
- *"Bouncing Spike — ดาเมจดูไม่ออก"*

## ⚠️ การตัดสินใจที่ฝังอยู่ในงานนี้ — อ่านก่อน

`Enemy.NotifyHitClientRpc(Vector3 pos, bool isCrit)` ยิงอยู่แล้ว**ทุกครั้งที่ศัตรูโดนตี**
และ **ไม่ได้ส่งค่าดาเมจมาด้วย** → จะโชว์เลขได้ต้องเพิ่ม `float damage` เข้าไป

RPC ตัวนี้คือตัวที่ audit ระบุว่าเป็น **ต้นทุน network ที่ใหญ่ที่สุดในเกม** (P1.1) และรายงาน
VFX pool ยืนยันแล้วว่า solo คนเดียวมี `HitEffect` ทำงานพร้อมกันถึง **559 ชิ้น**

**ทางที่เลือก**: เพิ่ม `float damage` (4 ไบต์) เข้า RPC ที่**มีอยู่แล้ว**
→ ไม่ได้เพิ่ม**จำนวนข้อความ** เพิ่มแค่**ขนาด** ซึ่ง P1.1 เป็นปัญหาเรื่องความถี่ ไม่ใช่ขนาด
→ ถ้าตัดสินใจ throttle ทีหลัง เลขดาเมจจะถูก throttle ตามไปเอง ไม่ต้องรื้อ

**ห้ามสร้าง RPC ตัวใหม่สำหรับเลขดาเมจเด็ดขาด** — นั่นคือเพิ่มความถี่ ซึ่งเป็นสิ่งที่กฎโปรเจกต์ห้าม

- **ห้ามเพิ่ม ServerRpc/ClientRpc ตัวใหม่ในเส้นทาง damage** — แก้ตัวที่มีอยู่ได้
