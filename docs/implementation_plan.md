## Context

เกมเป็น co-op 1-4 คน แต่ไม่มี UI ไหนแสดงผู้เล่นคนอื่นเลย — `GameHUD` เป็นของ local player
`WorldHPBar` ผูกกับ `Enemy` ผ่าน `[RequireComponent(typeof(Enemy))]` ใช้ซ้ำกับผู้เล่นไม่ได้

งานนี้เป็น **placeholder ที่ตั้งใจจะรื้อทิ้ง** ไม่ใช่ระบบถาวร เพราะฉะนั้น
**ข้อกำหนดสำคัญที่สุดคือความง่ายในการลบ ไม่ใช่ความสวยหรือความสมบูรณ์**

### กฎการออกแบบเพื่อให้รื้อทิ้งง่าย (สำคัญกว่าฟีเจอร์)

1. **ห้ามแก้ไฟล์เดิมแม้แต่ไฟล์เดียว** — สร้างไฟล์ใหม่ไฟล์เดียวจบ
2. **ห้ามสร้าง prefab / ห้ามแก้ scene / ห้ามให้คนต้องลาก reference ใน Inspector**
   สร้าง UI ทั้งหมดด้วยโค้ดตอน runtime
3. **ห้ามให้ระบบอื่นอ้างอิงถึงคลาสนี้** — ไม่มีใคร `GetComponent<TempPartyHUD>()`
4. bootstrap ตัวเองด้วย `[RuntimeInitializeOnLoadMethod]` → ไม่ต้องวาง component ในซีน
   → ลบไฟล์ทิ้งแล้วจะไม่เหลือ Missing Script ค้างในซีนหรือ prefab
   (แบบเดียวกับที่เพิ่งต้องตามลบ `ExperienceManager` ออกจาก `player.prefab` ด้วยมือ)

**ผลลัพธ์: วิธีรื้อทิ้ง = ลบ `Assets/Script/UI/TempPartyHUD.cs` ไฟล์เดียว จบ**

## Tasks

- [x] T1: สร้าง `Assets/Script/UI/TempPartyHUD.cs` (CREATE — ไฟล์ใหม่ไฟล์เดียว)

  **หัวไฟล์ต้องมี comment บอกชัดว่าเป็นของชั่วคราวและลบยังไง:**
  ```csharp
  /// <summary>
  /// ⚠ TEMPORARY — party HUD ชั่วคราว ตั้งใจให้รื้อทิ้งเมื่อมี UI จริง
  ///
  /// วิธีลบ: ลบไฟล์นี้ไฟล์เดียว จบ
  ///   — ไม่มีใครอ้างอิงถึงคลาสนี้
  ///   — ไม่ได้วางไว้ในซีนหรือ prefab (bootstrap ตัวเองตอน runtime)
  ///   — ไม่มี prefab / asset ที่ต้องตามลบ
  ///
  /// แสดงผู้เล่นทุกคนในห้องพร้อม HP ทั้งค่าฝั่ง server และค่า local
  /// กด F3 เปิด/ปิด
  /// </summary>
  ```

  **โครงสร้าง:**

  1. **Bootstrap** — ไม่ต้องวาง component เอง:
     ```csharp
     [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
     static void Bootstrap()
     {
         if (_instance != null) return;
         var go = new GameObject("~TempPartyHUD");
         _instance = go.AddComponent<TempPartyHUD>();
     }
     ```
     ชื่อขึ้นต้นด้วย `~` เพื่อให้เห็นชัดใน Hierarchy ว่าเป็นของชั่วคราวที่สร้างตอน runtime

  2. **สร้าง Canvas เองใน `Awake()`** — `ScreenSpaceOverlay`, `sortingOrder = 500`
     ใส่ `CanvasScaler` แบบ `ScaleWithScreenSize` (1920×1080) และ `GraphicRaycaster` **ห้ามใส่**
     (HUD นี้ไม่รับคลิก จะได้ไม่ไปบังปุ่มของ UI จริง)

  3. **Layout** — panel มุมซ้ายบน anchor `(0,1)` เว้นขอบ ~10px
     ใช้ `VerticalLayoutGroup` + `ContentSizeFitter` สร้างด้วยโค้ด
     พื้นหลังกึ่งโปร่ง `new Color(0f, 0f, 0f, 0.55f)`

  4. **สร้าง/อัปเดตแถวทุก 0.25 วินาที** (ไม่ใช่ทุกเฟรม — ตัวนี้เป็น debug tool ไม่ต้องลื่น):
     ```csharp
     var players = FindObjectsByType<playermove>(FindObjectsSortMode.None);
     ```
     เรียงตาม `OwnerClientId` เพื่อให้ลำดับคงที่ ไม่กระพริบสลับตำแหน่ง
     สร้าง row ใหม่เมื่อจำนวนไม่พอ นำ row เดิมกลับมาใช้เมื่อมากเกิน (`SetActive(false)`)

  5. **แต่ละแถวแสดง** (ใช้ `TextMeshProUGUI` — โปรเจกต์ใช้ TMP อยู่แล้ว):
     ```
     [HOST] id:0  Brawler   120 / 120   (local 120)
     [YOU ] id:1  Hunter     85 / 100   (local 100)
     ```
     - `[HOST]` เมื่อ `pm.OwnerClientId == NetworkManager.ServerClientId`
     - `[YOU ]` เมื่อ `pm.IsOwner` (แสดงได้ทั้งคู่ ถ้าเป็น host ตัวเอง)
     - ชื่อตัวละคร: `pm.GetComponent<PlayerVisual>()` → `GetCharacterData(v.CharacterIndex)?.characterName`
       ถ้าได้ null ให้แสดง `"?"` **ห้าม throw**
     - HP: `pm.netHealth.Value` / `pm.netMaxHealth.Value` ← **ค่าฝั่ง server**
     - `(local N)`: `pm.maxHealth` ← field ฝั่ง client
     - ตาย (`pm.isDead.Value == true`) → ต่อท้าย `" [DEAD]"` และเปลี่ยนสีข้อความเป็นเทา

  6. **⚠ ทำไมต้องโชว์ `netMaxHealth` คู่กับ `maxHealth`** — ใส่เป็นคอมเมนต์ในโค้ดด้วย:
     `netMaxHealth` คือค่าที่ server ตัดสิน ส่วน `maxHealth` เป็น local prediction ของ client
     ถ้าสองค่า **ไม่ตรงกัน** แปลว่า base stat sync เพี้ยน — HUD นี้จึงเป็นเครื่องมือยืนยัน
     audit 1.1 ไปในตัว ห้ามตัดค่าใดค่าหนึ่งออกเพื่อความสวยงาม

  7. **กด F3 toggle** — ใช้ `UnityEngine.InputSystem.Keyboard.current[Key.F3].wasPressedThisFrame`
     (โปรเจกต์ใช้ Input System อยู่แล้ว ดู `HunterUltimate.cs:65`)
     ต้องกัน `Keyboard.current == null`

  8. **ไม่มีผู้เล่นในซีน → ซ่อน panel ทั้งอัน** เพื่อไม่ให้โผล่ค้างใน MenuScene

## Acceptance Criteria

- คอมไพล์ผ่าน 0 error
- **`git status` ต้องขึ้นไฟล์ใหม่ไฟล์เดียว** — ไม่มีไฟล์เดิมถูกแก้เลยแม้แต่ไฟล์เดียว
- ไม่ต้องทำอะไรใน Unity Editor เลยก่อนใช้งาน (ไม่ต้องลาก ไม่ต้องสร้าง prefab)
- เข้าเกมแล้วเห็น panel มุมซ้ายบน แสดงผู้เล่นครบทุกคน

## Do NOT

- ห้ามแก้ไฟล์ `.cs` เดิมสักไฟล์ — **ถ้ารู้สึกว่าจำเป็นต้องแก้ ให้หยุดแล้วเขียนไว้ใต้ `## Questions`**
- ห้ามสร้าง prefab / ScriptableObject / แก้ scene
- ห้ามใส่ `GraphicRaycaster` (จะไปบังคลิกของ UI จริง)
- ห้ามเขียน `NetworkVariable` หรือเรียก ServerRpc — HUD นี้อ่านอย่างเดียว
- ห้ามทำให้คลาสนี้เป็น singleton ที่ระบบอื่นเรียกใช้ — ต้องไม่มีใครพึ่งพามัน
- ห้ามรันคำสั่ง shell / build / unity-check — Claude เป็นคนรันเอง
