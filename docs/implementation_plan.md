## บั๊กหลัก — บอสตายแล้วยังทำดาเมจต่อ

`BossController.OnDeath()` (`:190-199`) หยุดแค่ **coroutine ของตัวเอง** 2 ตัว
แต่กลไกที่ยิงออกไปแล้วเป็น **NetworkObject อิสระ ไม่มี back-reference กลับหาบอส**:

| ไฟล์ | บรรทัด | spawn อะไร |
|---|---|---|
| `Data/SpawnAoEActionBase.cs` | `:87` | TelegraphZone |
| `Data/ColorMatchAoEAction.cs` | `:63` | TelegraphZone |
| `Data/KeepMovingAction.cs` | `:106` | TelegraphZone |
| `Data/TetherAction.cs` | `:56` | BossTether |

→ ฆ่าบอสจังหวะที่ telegraph กำลังนับถอยหลัง = **ยังกินดาเมจจากบอสที่ตายไปแล้ว**

**ขอบเขตของอาการ (ตรวจแล้ว — ไม่ใช่ leak ถาวรอย่างที่ audit ทำให้เข้าใจ)**:
`TelegraphZone` despawn ตัวเองหลังจบ sequence (`:343`) · `BossTether` หลัง `duration = 6f` (`:177-185`)
→ หน้าต่างอาการคือ **~2.5 วินาที (telegraph) ถึง ~6 วินาที (tether)** ไม่ค้างตลอดเกม
แต่ยังเป็นบั๊กที่ผู้เล่นรู้สึกได้ชัด — ตายหลังจากฆ่าบอสไปแล้ว

**ทางเชื่อมที่มีอยู่แล้ว**: `BossAction.ExecuteCoroutine(NetworkBehaviour runner, ...)` —
`runner` คือบอสเอง และทั้ง `MainBoss` / `MiniBossAI` สืบจาก `BossController`
→ action เข้าถึง controller ได้ด้วย `runner as BossController` **ไม่ต้องเปลี่ยน signature**

    ```csharp
    // NetworkObject ที่ action ยิงออกไป (telegraph / tether) — ไม่มี back-reference กลับหาบอส
    // จึงต้องให้บอสถือทะเบียนเอง ไม่งั้นบอสตายแล้วของพวกนี้ยังระเบิดต่อ
    readonly List<NetworkObject> _activeMechanics = new();
    ```
    **ต้องมี `using System.Collections.Generic;` และ `using Unity.Netcode;`** — ถ้ายังไม่มีให้เพิ่ม
  - **เพิ่มเมธอด public** (วางใกล้ `SpawnExtraDrops`):
    ```csharp
    /// <summary>ให้ BossAction แจ้งว่ายิงกลไกอะไรออกไป — บอสจะเก็บกวาดให้ตอนตาย</summary>
    public void RegisterMechanic(NetworkObject no)
    {
        if (!IsServer || no == null) return;
        _activeMechanics.Add(no);
    }

    /// <summary>ลบกลไกที่ยังค้างอยู่ — เรียกตอนบอสตายหรือถูก despawn</summary>
    void CleanupMechanics()
    {
        for (int i = _activeMechanics.Count - 1; i >= 0; i--)
        {
            var no = _activeMechanics[i];
            if (no != null && no.IsSpawned) no.Despawn(true);
        }
        _activeMechanics.Clear();
    }
    ```
  - **เรียกใน `OnDeath()`** (`:190`) — เพิ่ม `CleanupMechanics();` **ก่อน** `SpawnExtraDrops();`
  - **เรียกใน `OnNetworkDespawn()`** (`:65`) ด้วย — เพิ่ม `CleanupMechanics();` หลัง `base.OnNetworkDespawn();`
    (กันเคสบอสหายไปโดยไม่ผ่าน `OnDeath` เช่นเปลี่ยนฉาก)
  - Expected: `BossController` มี `RegisterMechanic` เป็น public และเรียก `CleanupMechanics` 2 จุด

  > ⚠️ **กับดัก 3 ข้อ — อ่านก่อนเขียน**
  > 1. **ห้ามพยายาม prune list ระหว่างเกม** ของที่ despawn ตัวเองไปแล้วจะค้างเป็น entry ใน list
  >    ซึ่ง**ไม่เป็นไร** — `CleanupMechanics` เช็ค `!= null && IsSpawned` อยู่แล้ว และอายุบอสมีขอบเขต
  >    การเพิ่ม coroutine มาไล่เก็บคือ over-engineer
  > 2. **ห้ามเปลี่ยน `deathHandled` หรือ signature ของ `OnDeath`** — มันเป็น `protected virtual`
  >    ที่ `MainBoss`/`MiniBossAI` override อยู่
  > 3. `Despawn(true)` จะทำลาย object ที่อาจมี coroutine ของตัวเองทำงานอยู่ — **ปลอดภัยแล้ว**
  >    เพราะ `TelegraphZone:343` และ `BossTether:91` เช็ค `NetworkObject.IsSpawned` ก่อน despawn ตัวเอง
  >    **ห้ามไปแก้สองไฟล์นั้น**
