# ADR-004: วาด telegraph ด้วย quad ใบเดียว + SDF

**Status:** ❌ **Rejected** — ไม่ทำ · เก็บไว้เป็นบันทึกกันคนเสนอซ้ำ
**Date:** 2026-08-12
**Deciders:** เจ้าของโปรเจกต์
**คำถามตั้งต้น:** ขอบ outline ไม่อยู่ที่ขอบ object · หนาไม่เท่ากันเมื่อ scale ไม่เท่ากัน · ไม่โผล่บนแกน x/y

> ## ทำไมถึงไม่ทำ
>
> **โจทย์จริงคือ outline อย่างเดียว ซึ่งไม่ต้องรื้ออะไรเลย** — แก้ด้วยการคูณ `Object.Scale`
> เพื่อแปลงระยะเป็นหน่วยโลก เพิ่มไม่กี่โหนดในกราฟเดิม จบ
>
> เอกสารนี้เอาปัญหาที่ค้นเจอระหว่างทาง (บั๊ก `innerRadius` ของโดนัท) มาผูกกับคำขอเดิม
> แล้วสรุปว่าต้องเปลี่ยนสถาปัตยกรรม ทั้งที่เป็นคนละเรื่องที่บังเอิญอยู่ไฟล์เดียวกัน
>
> **และเดินย้อนทิศที่โปรเจกต์เลือกไว้** — git บอกว่า `CreateVisual()` (ปั้นตอนรัน) มาก่อน
> แล้ว `73906636` เพิ่ม `TrySpawnVfxPrefab()` มาแทนอย่างตั้งใจ · ข้อเสนอนี้คือการถอยกลับ
> ไปทางเดิมโดยไม่ได้ดูประวัติก่อน
>
> ระบบปัจจุบันผ่านการเล่นจริงเกือบหมดแล้ว การรื้อเส้นทาง visual ทั้งชุดแลกกับ outline
> ที่หนาเท่ากัน เป็นการแลกที่ไม่คุ้ม
>
> **สิ่งที่ทำจริงแทน** — patch `Object.Scale` · Pulsating rings หน่วยเมตร · ปุ่มความแรงต่อเอฟเฟกต์
>
> **ข้อที่ยังจริงและควรแก้แยก** — `innerRadius` ของโดนัทไม่มีผลกับภาพ เพราะโค้ดส่งค่าเข้า
> `VisualEffect` แต่ prefab ไม่มี `VisualEffect` สักตัว

> ต่อจาก [ADR-003](adr-003-ffxiv-rns-mechanic-gaps.md)
> **สถานะการเทสต์ ณ วันที่เขียน:** ของจาก ADR-002/003 ผ่านการเล่นจริงเกือบหมดแล้ว
> เหลือ **roll** กับ **cone** ที่ยังไม่ได้ยืนยัน

## Context

### อาการที่รายงาน

1. ขอบไม่อยู่ที่ขอบของ object
2. ขอบหนาไม่เท่ากันเมื่อ cube scale ไม่เท่ากัน
3. ไม่แสดงบนแกน x / y

### ต้นเหตุตรง — สูตรที่วางไว้คิดระยะใน object space

กล่อง 1×1×1 มีพิกัด object space เป็น −0.5..0.5 **เท่ากันทุกแกนเสมอ** ไม่ว่า transform จะ scale เท่าไหร่
แถบขอบจึงกว้างเป็น **สัดส่วน** ของแต่ละแกน ไม่ใช่ความหนาคงที่

Line ที่ scale `(1.5, 1, 8)` ได้ขอบด้านปลายหนากว่าด้านยาวราว 5 เท่า — ตรงกับอาการข้อ 2
ส่วนผนังข้าง (±X, ±Z) มีระยะถึงขอบ = 0 พอดี จึงติดแถบเต็มผืน — ตรงกับอาการข้อ 3

**เป็นข้อจำกัดของสูตร ไม่ใช่การต่อโหนดผิด** และแก้ด้วยการคูณ `Object.Scale` กลับได้
แต่ยังเหลือปัญหาผนังข้าง และไม่ได้แก้ต้นเหตุที่ลึกกว่า

### ต้นเหตุที่ลึกกว่า — ภาพกับ hit test เป็นคนละ implementation

| | มาจากไหน |
|---|---|
| **ภาพ** | mesh สำเร็จรูป scale ด้วย transform |
| **ดาเมจ** | คณิตล้วนบน `transform` + พารามิเตอร์ · `IsInCircle` / `IsInLine` / `IsInDonut` / `IsInCone` |

grep แล้ว **เส้นทางคิดดาเมจไม่แตะ mesh หรือ collider เลยแม้แต่ที่เดียว** — ไม่มี `Collider`, `Physics.`, `bounds`
`sharedMesh` โผล่ครั้งเดียวคือตอนสร้าง visual ของ Cone

สองระบบนี้จึงเพี้ยนจากกันได้เงียบๆ **และเพี้ยนอยู่แล้วจริงๆ**

> `TrySpawnVfxPrefab` scale โดนัทเป็น `(radius×2, 1, radius×2)` แล้วส่ง `innerRadius`
> เข้า `VisualEffect` — แต่ prefab ทั้งสามตัว**ไม่มี `VisualEffect` สักตัว**
> `innerRadius` จึงไม่มีผลกับภาพโดนัทเลย รูตรงกลางถูกล็อกไว้ที่ mesh
> **ปรับ `innerRadius` = เซฟโซนที่เห็นไม่ขยับ แต่ที่ปลอดภัยจริงขยับ**

### ผลสำรวจที่ทำให้เปลี่ยนสถาปัตยกรรมได้ถูก

| ตรวจอะไร | ผล |
|---|---|
| `AoEType_Circle` / `_Line` / `_Donut` | **Cylinder ในตัว Unity (10206) · Cube (10202) · mesh ไฟล์เดียว** — ไม่มี VFX Graph ไม่มีงานศิลป์ ทิ้งแล้วไม่เสียอะไร |
| URP renderer features | **ว่าง** — Decal ยังไม่เปิด ถ้าจะใช้ต้องเพิ่ม pass |
| `SampleScene` | **ไม่มี Terrain** พื้นเป็นกล่องแบน 80×80 จาก `LevelLayoutBuilder` — decal ไม่ได้เปรียบ quad |
| ShaderGraph 17.7 | มี node รูปทรงในตัว (`Ellipse` `Rectangle` `Rounded Rectangle` `Polygon`) |

## Decision

### 1 · quad แบนใบเดียว วาดรูปทรงด้วย SDF ในเชเดอร์

เลิกใช้ mesh ต่อทรง · รูปทรงมาจากคณิตใน fragment โดยรับขนาดเป็น **uniform หน่วยเมตร**
ซึ่งเป็นพารามิเตอร์ชุดเดียวกับที่ hit test ใช้อยู่แล้ว

แก้ทั้งสามอาการด้วยโครงสร้าง ไม่ใช่ไล่แปะทีละข้อ

- ขอบหนาคงที่ เพราะเทียบระยะหน่วยโลกกับ `_OutlineWidth` หน่วยโลก
- ไม่มีผนังข้างให้แดง เพราะเป็นระนาบไม่ใช่กล่อง
- Cone ไม่ต้องปั้น mesh ตอนรันอีก
- `innerRadius` ของโดนัทกลับมามีผลกับภาพ

### 2 · ต่อใน `TelegraphUniversal` เดิม ไม่สร้างกราฟใหม่

pulse · fresnel · `_FillProgress` ที่ lerp `_WarningColor → _DangerColor` · การรับสีตามหมวดกลไก
**ใช้ต่อได้ทั้งหมด** สิ่งที่เปลี่ยนคือ**ส่วน mask รูปทรง**เท่านั้น

โหนด outline ที่เพิ่งลากไปจะถูกแทนด้วย SDF ซึ่งให้ขอบหน่วยเมตรจริงโดยไม่ต้องคูณ scale
`Tele_outline.shadergraph` กับ `Mat_Tele_OutLine.mat` จะไม่ได้ใช้ — inverted hull ต้อง 2 pass
ซึ่ง ShaderGraph target ของ URP ทำไม่ได้

### 3 · quad หน่วยเดียว scale เท่ากันทุกแกน · เชเดอร์อ่าน `Object.Scale` เอง

C# ส่งแค่ `radius` `lineWidth` `lineLength` `innerRadius` `coneAngle` เป็นเมตร — ค่าที่มีอยู่แล้ว
ไม่ต้องคำนวณอะไรเพิ่ม และ **ไม่มีทางที่ scale จะบิดรูปทรง** เพราะ quad เป็นสี่เหลี่ยมจัตุรัสเสมอ

ขนาด quad = กรอบครอบรูปทรง (`radius×2` · `max(lineWidth, lineLength)` · ฯลฯ)

### 4 · ลบเส้นทาง primitive เดิมทิ้ง

`CreateVisual` / `CreateConePrimitive` / `CreateCylinderPrimitive` / `CreateLinePrimitive` / `CreateSafeCylinderPrimitive`

การมี visual สองชุดคือสาเหตุที่บั๊ก `innerRadius` รอดมาได้นาน · quad prefab หายเมื่อไหร่ให้ **log error**
ไม่ใช่เงียบแล้ววาดอย่างอื่นแทน

### 5 · ขอบคมด้วย `Step` ไม่ใช้ AA

เกมเป็น **3D top-down** กล้องอยู่ระยะคงที่ ขอบหยักจึง**นิ่ง ไม่ยิบยับ** ต่างจากกล้องอิสระ

**ยอมรับข้อแลก:** ทรงโค้ง (Circle / Donut / ส่วนโค้งของ Cone) จะเห็นขั้นบันไดชัดกว่าทรงตรง
ถ้าเปลี่ยนใจภายหลัง เติม `smoothstep` คู่ `fwidth` แค่ 2 โหนด ไม่ต้องรื้ออะไร

### 6 · Gizmo วาดรูป hit test จริงใน Scene view

`OnDrawGizmos` บน `TelegraphZone` วาดวง/กล่อง/โดนัท/กรวย จาก**สูตรเดียวกับ `IsInXxx`**

ภาพกับ hit test ยังเป็นคนละ implementation อยู่ดี (C# กับ HLSL แชร์โค้ดกันไม่ได้)
Gizmo คือตัวที่ทำให้ความเพี้ยน**มองเห็นได้ตอนออกแบบ** แทนที่จะไปเจอตอนผู้เล่นด่า
— อันนี้จะจับบั๊ก `innerRadius` ได้ตั้งแต่นาทีแรก

### 7 · hit test ฝั่ง server ไม่แตะเลยสักบรรทัด

## Trade-off Analysis

**สิ่งที่ยอมแลก** — เชเดอร์จะซับซ้อนขึ้นมาก จากเดิมที่แทบไม่มีคณิตเชิงพื้นที่เลย
(กราฟปัจจุบันไม่มีแม้แต่ UV หรือ Position node) กลายเป็นมี SDF 5 ทรงกับตัวเลือกทรง
คนที่มาแก้ทีหลังต้องอ่านกราฟเป็น

แต่แลกกับการที่**รูปทรงมาจากพารามิเตอร์ชุดเดียวกับดาเมจ** ซึ่งเป็นสิ่งที่ mesh ทำไม่ได้เลย

**สิ่งที่ไม่ยอมแลก** — ไม่แตะ hit test · การเปลี่ยนภาพต้องไม่มีทางเปลี่ยนดาเมจ
ถ้าจบงานแล้วดาเมจเพี้ยนแปลว่าทำผิดทาง ไม่ใช่ balance

## Consequences

**ง่ายขึ้น** — เพิ่มทรงใหม่ = เพิ่มสูตร SDF ไม่ต้องทำ prefab ไม่ต้องปั้น mesh
`scaleStart/scaleEnd` ที่ตอนนี้ scale ทั้ง transform จะกลายเป็นการ animate รัศมีในเชเดอร์
ซึ่ง**ถูกกว่าเดิม** เพราะขอบจะไม่ขยายตามวง

**ยากขึ้น / ต้องระวัง**

1. **z-fighting กับพื้น** — ของเดิมยกลอย 0.02 · quad ต้องทำเหมือนกันหรือใช้ depth offset
2. **overdraw** — telegraph โปร่งใสหลายใบซ้อนกันบนพื้น ยิ่ง quad ครอบกรอบใหญ่กว่ารูปทรงจริง พื้นที่โปร่งใสยิ่งเยอะ · ต้อง discard พิกเซลนอกทรงตั้งแต่เนิ่น
3. **Quad ในตัว Unity หันหน้า +Z** ต้องหมุน X 90° ให้นอนราบ — พลาดตรงนี้จะได้ telegraph ตั้งฉากกับพื้น
4. **`Cross` = `min` ของสองสี่เหลี่ยม** ไม่ใช่ mesh สองใบอีกต่อไป

**ต้องกลับมาทบทวน** — ถ้าวันหนึ่งพื้นมีต่างระดับหรือมีทางลาด quad แบนจะลอยเหนือ/จมพื้น
ตอนนั้นค่อยย้ายไป Decal ซึ่งโครงที่วางไว้รองรับได้เพราะรูปทรงอยู่ในเชเดอร์อยู่แล้ว

## ต้องเทสต์ด้วยมือ

| ทำอะไร | ต้องเห็นอะไร |
|---|---|
| Line ที่ `lineWidth` ต่างจาก `lineLength` มากๆ | **ขอบหนาเท่ากันทุกด้าน** |
| มองจากมุมกล้องเกมจริง | ไม่มีผนังข้างแดง · ไม่มี z-fight กับพื้น |
| ปรับ `innerRadius` ของโดนัท | **รูตรงกลางขยับตาม** (ตอนนี้ไม่ขยับ) |
| เปิด Gizmo แล้วเทียบกับภาพ | รูปซ้อนกันสนิททุกทรง |
| `scaleStart → scaleEnd` วงขยาย | **ขอบหนาเท่าเดิมตลอด** ไม่ขยายตามวง |
| Cone | มุมและรัศมีตรงกับที่ตั้ง · ตรงกับ Gizmo |
| telegraph หลายใบซ้อนกัน | เฟรมเรตไม่ตก · สีทับกันอ่านออก |
| ถอด quad prefab ออกจาก TelegraphZone | **เห็น error ใน Console** ไม่ใช่เงียบ |

### ยังค้างจาก ADR-003 (ไม่เกี่ยวกับงานนี้)

- **roll** — ยังไม่ได้ยืนยัน · ต้องผูก `rollName` ให้ action ก่อนถึงจะเห็นผล
- **cone** — ยังไม่ได้ยืนยัน · งานนี้จะเปลี่ยนวิธีวาดมันอยู่แล้ว รอเทสต์รอบเดียวหลังจบ
