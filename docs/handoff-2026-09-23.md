### สูตร compile-check ที่ใช้ได้กับทุกเวอร์ชัน

อย่าฝังเลขเวอร์ชัน — โปรเจกต์ย้าย a2 → a3 → b1 มาแล้วสามรอบ:

```bash
VER=$(head -1 ProjectSettings/ProjectVersion.txt | cut -d' ' -f2)
ED="E:/Zenity Why not/Unity/$VER/Editor"
CSC=$(ls "$ED"/Data/DotNetSdk/sdk/*/Roslyn/bincore/csc.dll | head -1)
RSP=$(ls -t Library/Bee/artifacts/*.dag/Assembly-CSharp.rsp | head -1)

grep -v -e '^-out:' -e '^-refout:' "$RSP" > <scratch>/AC.rsp
printf -- '-out:"<scratch>/AC-check.dll"\n' >> <scratch>/AC.rsp
"$ED/Data/DotNetSdk/dotnet.exe" "$CSC" "@<scratch>/AC.rsp"
```

เช็ค `Assembly-CSharp-Editor` **เทียบกับ runtime ที่เพิ่งแพตช์** ด้วย โดยชี้ `-r:` ของ
`Assembly-CSharp.ref.dll` ไปที่ `AC-check.dll` ที่เพิ่ง build — จับ editor code ที่เรียก signature ที่เพิ่งเปลี่ยน

## 3 · งานที่เพิ่งเสร็จ — Boss Designer

เริ่มจาก `/scrutinize` แล้วพบว่าหน้าต่างนี้แก้แกน **เวลา** ที่ง่ายอยู่แล้ว
แต่ไม่แตะสองแกนที่ทำให้แพตเทิร์นเป็นแพตเทิร์นจริงๆ คือ **ตำแหน่ง** กับ **ความสุ่ม**

หลักฐานที่วัดออกมาได้: `BossConfig_01` นิยาม roll ไว้ 5 ตัว (mirror · spin · quadrant · victim · order)
แล้ว **ไม่มี action ตัวไหนในเกมอ้างเลยสักตัว** — ระบบที่มี ADR สองฉบับรองรับ สร้างเสร็จแล้วไม่มีใครใช้
เพราะ `rollName` เป็นช่องพิมพ์เปล่า และพรีวิวไม่มี

### `250ae6c2` — ให้ runtime เดินตรงกับเส้นเวลาที่วาด

- **run generation** ใน `BossController` — ท่าจดเลขรอบตอนเริ่ม เช็คก่อนลงมือ รอบเปลี่ยน = ทิ้งตัวเอง
  แก้อาการคลิปของเฟสเก่ายิงทับเฟสใหม่ (`BossTimelineAction` ยิง coroutine อิสระที่ไม่มีใครถือ handle)
  บวก `CleanupMechanics()` ตอนเปลี่ยนเฟส เพราะเลขรอบกันได้แค่ท่าที่ยัง**ไม่**ลงมือ
- **`waitForTimelineEnd` รอ coroutine จริง** ไม่รอนาฬิกาจาก `GetEditorDuration()`
  → สัญญาใหม่: **`ExecuteCoroutine` คืนค่าเมื่อกลไกจบ ไม่ใช่เมื่อยิงออกไปแล้ว**
  (`SpawnAoEActionBase` รอ `warningDuration` · `TetherAction` รอ `tetherDuration` · `ColorMatch` เช่นกัน)
- **`firstAttackDelay` จ่ายครั้งเดียวตอนเกิด** — เดิม restart `AttackLoop` ทุกเฟสเลยจ่ายซ้ำ
  ช่องว่างตอนเปลี่ยนเฟส 5.5s → 1.5s และคลิปที่วางไว้ที่ t=0 ยิงที่ 0 จริง

ผลกับ content: เฟส 1 รอบละ 14.6s → 14.1s · เฟส 2/3 เท่าเดิม (tether 8s เป็นตัวยาวสุด)

### `1d33741c` — ทำให้ roll กับตำแหน่งมองเห็นได้

- **`[RollId]` dropdown** (`RollIdDrawer`) — รายการเขียนชนิดต่อท้ายชื่อ `spin · SnapAngle ×4`
  ค่าที่ผิดโชว์พร้อมป้าย "ไม่มีนิยาม" ไม่เด้งเป็นค่าแรกให้เอง
  บวก `RollContext.Roll` warn ตอนรัน เพราะ drawer ครอบได้แค่ทางที่ผ่าน Inspector
- **`AoEWorld`** — ข้อเท็จจริงของโลก (บอสอยู่ไหน · ผู้เล่นอยู่ไหน · สนามเป็นยังไง · roll)
  ทำให้ **`SpawnAoEActionBase.ResolveWave()` เป็นนิยามเดียว** ของ "ท่านี้ลงตรงไหน"
  ที่เซิร์ฟเวอร์ · พรีวิว · ตัวตรวจ เรียกตัวเดียวกัน ต่างแค่ world ที่ป้อน
  `FindNearestPlayer` / `CollectAlivePlayerPositions` ยุบเข้า `AoEWorld` ไม่เหลือนิยามที่สอง
- **`ArenaPreview`** — แผนผังสนามที่ playhead อยู่ติดช่องแก้ค่าในแผงขวา + ปุ่ม 🎲 เปลี่ยน seed
  ⚠️ ขนาดของทรงอ่านด้วย **reflection** จากฟิลด์ชื่อเดียวกับที่ `TelegraphZone` ใช้
  (เพราะ `ConfigureTelegraphZone` เรียกจาก editor ไม่ได้) · เปลี่ยนชื่อฟิลด์แล้วจะขึ้นป้าย
  "ไม่รู้ขนาด" บนจอ ไม่ใช่วาดวงขนาด 0 เงียบๆ — เห็นป้ายนี้บ่อยเมื่อไหร่แปลว่าถึงเวลายก
  `AoEShape` ขึ้นเป็น struct ที่ทั้งสองทางใช้ร่วมกัน
- **`BossConfigAudit`** — `Tools > Clone Swarm > Audit Boss Configs` · มี entry สำหรับ batchmode ·
  ต่อเข้า `P3RSmokeTest` แล้ว (`CheckBossConfigs`) · ไล่ทุก action รวมที่ซ้อนใน timeline/combo/pool

## 4 · เครื่องมือที่มีให้ใช้

```bash
# ตรวจ config บอสทั้งโปรเจกต์ โดยไม่ต้องกด Play (~1 นาที)
"$ED/Unity.exe" -batchmode -nographics -projectPath "E:/Zenity Why not/cloneSwarm" \
  -executeMethod CloneSwarm.EditorTools.BossConfigAudit.RunBatch -logFile "<abs>/audit.log"
```

exit 1 = มีข้อผิดจริง · ผลรอบล่าสุด: `config 4 ใบ · action 19 ตัว · ResolveWave ผ่าน 11 ครั้ง · roll นิยาม 5 / ใช้จริง 0`

`-logFile` **ต้องเป็น absolute path** ไม่งั้น Unity ออก 127 แต่ pipeline รายงาน exit 0 (ดู `p3r-proto-screen-loop`)

### 5.2 · บั๊ก content ที่ audit จับได้

```
FAIL  MiniBossConfig "Purple 1" · DonutAoEAction
      targetingMode = ArenaAnchor แต่ config ไม่ได้ผูก arena
      → runtime ถอยไปใช้ตำแหน่งบอส วงโผล่ผิดที่ทั้งชุด
```

เลือกได้สองทาง: ผูก arena ให้มินิบอส หรือเปลี่ยนเป็น `BossPosition`
(เดาว่าทางหลัง เพราะมินิบอสเกิดกระจายทั้งแมพ ไม่ได้อยู่ในสนามตายตัวเหมือนบอสใหญ่ — แต่เป็นการตัดสินใจเชิงออกแบบ)

### 5.3 · ต้องมีคนเปิดดู

- **ภาพในเกมหลังอัปเกรด** — URP 17.7 เปลี่ยน settings จริง ไม่ใช่แค่ churn
  (`DefaultVolumeProfile` +85 บรรทัด · `UniversalRenderPipelineGlobalSettings` +91)
- **`ArenaPreview` วาดออกมาถูกไหม** — เปิด `Tools > Boss Designer`
- **อาการค้างตอนกด QUIT** — สรุปไว้ว่ามาจาก CoreCLR (`scriptingBackend: Standalone: 3`)
  ยังไม่ได้ลองใหม่บน b1 · beta อาจแก้แล้ว คุ้มลองก่อนตัดสินใจย้ายกลับ Mono

### 5.4 · คิวถัดไปของระบบบอส (จากรีวิวเดิม ยังไม่ทำ)

- `RandomAttackAction` ยังสุ่มด้วย `Random.Range` ไม่ผ่าน `RollContext` →
  `FightSeed` reproduce fight ที่ใช้ท่านี้ไม่ได้ · และเป็น container ตัวเดียวที่ไม่เรียก `RollForSubActions`
  (คอมมิตล่าสุดใส่ให้แค่เลขรอบ) · น่าขันคือ `TetherAction` เขียนสอนไว้เองว่าให้ใช้ pool ของตัวนี้เพื่อสุ่ม
- **enrage ทำงานตอนจบ timeline ไม่ใช่ตอน `enrageTime`** เพราะ `AttackLoop` ค้างอยู่ในท่าทั้งเส้น
  ป้าย `enrage 20s →` บน encounter graph จึงบอกเวลาที่ไม่จริง
- `mechanicIndex` ไม่ reset ตอนสลับเข้า enrage — เริ่มที่ index สุ่ม ไม่ใช่ท่าแรก
- `BossController.phase2Threshold` / `phase3Threshold` เป็น dead code ที่เขียนหัวข้อว่า "for BossHUDUI" แต่ไม่มีใครอ่าน
