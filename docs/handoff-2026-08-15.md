## 1 · สถานะการเทสต์ — อ่านข้อนี้ก่อน

**ยังไม่ได้กด Play เลยสักครั้งตลอดทั้งเซสชัน**

สิ่งที่ยืนยันแล้วมีแค่สองอย่าง — คอมไพล์ผ่าน 0 error และ EditMode test 44/44 ผ่าน
ซึ่ง**ทั้งหมดเป็นคณิตล้วน** (`ShieldStack` 13 ตัว · `TelegraphGeometry` 22 ตัว) ไม่ได้แตะพฤติกรรมในเกม

รอบนี้แก้บั๊กที่กระทบ "ความรู้สึก" หลายตัวพร้อมกัน การเล่นจริงจึงไม่ใช่ขั้นตอนตรวจทาน
แต่เป็นขั้นตอนที่จะบอกว่าต้องรีบาลานซ์ตรงไหน

## 2 · สี่บั๊กที่แก้ และสิ่งที่จะรู้สึกได้

### โล่เติมตัวเองกลับหลังกันดาเมจ

`playermove` คำนวณการสลายด้วย `Lerp(shieldAtLastAdd, 0, elapsed/dur)` ทุกเฟรม
แต่จุดที่หักโล่ตอนโดนตีไม่ได้อัปเดต `shieldAtLastAdd` เฟรมถัดไปจึงเขียนทับผลของการกันดาเมจ

```
โล่ 100 → สลายเหลือ 66.7 → โดนตี 50 เหลือ 16.7 → เฟรมถัดไปเด้งกลับเป็น 60
```

**โล่ทุกใบในเกมทนกว่าตัวเลขที่ออกแบบไว้มาตลอด** ตอนนี้ตรงตามตัวเลขแล้ว = อ่อนลงจากที่เคยเล่น
อาจต้องขยับ `shieldPercent` ของ BunnyHop ชดเชย · มีเทสต์ `AbsorbThenDecay_DoesNotRestoreAbsorbedAmount_RegressionForADR008CriticalBug` กันไว้แล้ว

### บัฟ Support Arena ค้างถาวร

เสาเรียก `RemoveBuffs` ผ่าน reference ไปยังอาวุธ ซึ่ง `ReplaceWeapon` สั่ง Destroy ตอนอัปเป็น Super
→ guard `if (weapon != null)` ตัดการล้างบัฟทิ้ง ทุกคนในวงได้ +20% ดาเมจ/ความเร็ว/haste ตลอดเกม

### ดาเมจเข้าสองเท่า

ศัตรูมี collider ได้หลายตัวบน GameObject เดียวกัน (`TargetDummy` มี trigger + solid)
`OverlapEnemy` คืนทั้งคู่ ผู้เรียกจึงตี `EnemyTakeDamage` ซ้ำ

**เลข DPS ที่อ่านจาก WeaponTestScene ก่อนหน้านี้สูงกว่าความจริงเท่าตัว** — ตัวเลขบาลานซ์
ที่เคยจูนโดยดูจากตรงนั้นควรตรวจใหม่ทั้งหมด

ศัตรูจริงมี collider ตัวเดียวจึงไม่กระทบ ที่เปลี่ยนคือดัมมี่

### คริติเข้าดาเมจแต่ไม่มีเอฟเฟกต์บอก

`GrenadeProjectile` ไม่มีฟิลด์ `isCrit` เลย ค่าที่ RPC รับมาถูกทิ้งเงียบ — คริติหายทั้งตระกูลระเบิด
rocket / missile / mine / chain-lightning ก็ไม่ส่งต่อเหมือนกัน

**ไม่มีตัวเลขไหนขยับ แต่จะรู้สึกเหมือนดาเมจพุ่งบ่อยขึ้นมาก** เพราะคริติมองเห็นได้ทั่วเกม
เป็นครั้งแรก · ถ้ารู้สึกว่า `CritHitEffect` เด้งถี่จนรก นั่นคือค่าคริติจริง ไม่ใช่บั๊กใหม่

## 3 · ค่าที่ "เพิ่งมีชีวิต" — ต้องจูนแน่ๆ

ของพวกนี้ตั้งไว้นานแล้วแต่ไม่เคยมีผล พอต่อสายแล้วมันทำงานทันทีด้วยค่าที่ไม่เคยผ่านการจูน

| ค่า | เดิม | ตอนนี้ |
|---|---|---|
| `fuseTime` (ทุกระเบิด) | ไม่เคยถูกอ่าน | Splitter Bomb นอนรอ **1.2 วิ** ก่อนระเบิด · Cluster Bomb 1.0 / ลูกย่อย 0.6 |
| `evoRegenBonus` | ไม่เคยต่อสาย | Support Arena evo ฟื้นเลือด +2/วิ |
| Orbiter `cooldown`/`duration` | ทิ้ง ใช้ค่า prefab คงที่ | ไล่ตาม level curve — uptime เลเวล 5 พุ่งจาก 38% เป็น **95%** |
| Ability Haste กับ Orbiter | ไม่มีผลเลย | มีผลแล้ว |
| การ์ดเพิ่มกระสุนกับ Orbiter | ไม่มีผลเลย | เพิ่ม orb จริง และ rebuild ทุกรอบ |

**Orbiter คือตัวที่เสี่ยงแรงเกินที่สุด** — ค่าบน prefab (cd 8, duration 5) น่าจะถูกจูนขึ้นมาชดเชย
ตอนที่ยังไม่รู้ว่า WeaponData ไม่ถูกอ่าน · ถ้าแรงเกิน **แก้ที่ `WD_Orbiter` ไม่ใช่ที่ prefab**
เพราะตอนนี้ WD ชนะแล้ว

## 4 · บั๊กที่รู้แล้วยังไม่แก้

**Orbiter สร้าง orb กำพร้าบนเครื่องคนอื่น** — `OnInit` ไม่ได้ gate ด้วย owner แต่ `Update` gate
orb จึงถูกสร้างและเปิดมองเห็นบนทุกเครื่อง แต่ไม่มีอะไรอัปเดตตำแหน่งหรือปิดมัน ค้างอยู่ที่
พิกัด (0,0,0) ขนาด `orbSize: 3` หนึ่งชุดต่อผู้เล่นทางไกลหนึ่งคน
· **อ่านจากโค้ดล้วน ยังไม่ได้ทดสอบสองเครื่อง**

**เส้นทาง raycast ยังตีซ้ำได้** — `FireRaycastServerRpc` / `FireRaycastChainServerRpc` ไม่ผ่าน
`OverlapEnemy` จึงยังไม่ de-dup · Laser / Railgun / ThunderRail อยู่กลุ่มนี้

**โซนสายฟ้ามาช้า** — `SpawnLightningZonesServerSide` วาง `WaitForSeconds` ไว้ต้นลูป tick แรกจึง
หน่วง 0.3 วิ · ThunderRail ตั้ง `zoneTicks: 1` แปลว่าโซนทั้งก้อนเกิดหลังลำแสงโดน 0.3 วิ และ
ตอนโดนจริงไม่มีอะไรเลย (ทั้งสองอาวุธส่ง `hitVfx: "None"`) · ย้าย `WaitForSeconds` ไปท้ายลูปก็จบ
แต่กระทบ Molotov/Napalm ที่ใช้ฟังก์ชันเดียวกัน

**สตริง VFX ดิบอีก 7 จุด** ที่การสำรวจของ ADR-006 นับพลาด (ไล่เฉพาะ `PlayByName` แต่ส่วนใหญ่
เรียกผ่าน `VFXFactory.Play`) · รายชื่ออยู่ใน ADR-006 §Context แล้ว

**หนี้ข้อ 2 ใน ADR-007** — ค่าใน `.mat` ไม่เคยมีผลเพราะ MPB เขียนทับทุกเฟรม designer เปิด
material inspector ไปหมุนค่าแล้วไม่มีอะไรเกิดขึ้น · เป็นการตัดสินใจว่าใครเป็นเจ้าของค่า ไม่ใช่งานลบ

## 5 · งาน Editor ที่โค้ดทำแทนไม่ได้

- **แยก prefab ให้ Blunderbuss** — ตอนนี้ใช้ `ShotgunWeapon.prefab` ตัวเดียวกับ Shotgun ที่ตั้ง
  `explodeOnHit: 0` · โค้ดพร้อมแล้ว (pellet ระเบิดตรงจุดชน) แต่เปิดสวิตช์ตรงนั้นร่างธรรมดาจะระเบิดตาม
- **`VFXAsset.category` ทั้ง 23 ตัว** — ตอนนี้เป็นค่าที่สคริปต์เดาจากชื่อ key
- **`Enemy.deathVfx`** ว่างบนทุก prefab (ยังทำงานผ่าน fallback + warning ครั้งเดียว)
- **`detonateVfx` ว่าง 16 จุด** — ทุก AoE ของบอสระเบิดหน้าตาเหมือนกันหมดจนกว่าจะตั้ง
- **`arenaDiscMaterial` / `pillarBodyMaterial`** บน `SupportArenaWeapon` ทั้งสอง prefab
- **`clusterProjectilePrefab`** ต้องตั้งบน prefab ลูกระเบิดเสมอ — prefab reference ส่งข้ามเน็ตเวิร์กไม่ได้
  เป็นช่องเดียวของ Splitter Bomb ที่ยังต้องเปิดสองที่

## 6 · บทเรียนวิธีทำงานจากรอบนี้

**`GetInstanceID()` ถูก deprecate ใน Unity 6000.7 และ CS0619 นับเป็น error ในโปรเจกต์นี้**
ต้องเก็บ `Enemy` ไว้ใน `HashSet` เทียบ reference แทน · เสียเวลาไปหนึ่งรอบคอมไพล์กับเรื่องนี้

**การสำรวจที่ไล่เฉพาะชั้นล่างสุดจะนับพลาด** — ADR-006 ไล่ `PlayByName` แล้วสรุปว่าเหลือสตริงดิบ
ตัวเดียว แต่ 7 ใน 8 จุดเรียกผ่าน `VFXFactory.Play` ซึ่งเป็นชั้นบางๆ ที่เรียกต่ออีกที
· เวลาสำรวจ ให้ไล่ทั้ง wrapper ด้วย

**บั๊กที่มีคนแก้เฉพาะไฟล์ตัวเองแล้วไม่บันทึก จะทิ้งจุดอื่นไว้พัง** — `StormBunnyWeapon` มี
`HashSet` กันศัตรูซ้ำเขียนไว้เอง ไม่มีคอมเมนต์ ไม่มีบันทึก อีกสี่จุดจึงยังตีซ้ำอยู่จนถึงรอบนี้
· รูปแบบเดียวกับที่ `review-ngo` บันทึกไว้ว่าเคยเกิดกับ `EnemySpawner`

**ตรวจข้อเท็จจริงก่อนรายงาน** — ในเซสชันนี้ผมรายงานผิดหลายครั้งแล้วต้องแก้: บอกว่า
`TargetDummy.prefab` ไม่มี ทั้งที่มี · บอกว่า `GrenadeWeapon` ส่งคริติถูกครบสาย ทั้งที่ตกที่ RPC ·
บอกว่าไม่มีอะไรต้องย้อน ทั้งที่ถูกลงมือไปแล้ว · ทุกครั้งเกิดจากการเชื่อผลคำสั่งที่ตัดผลลัพธ์
(`head`) หรือเดาจากชื่อแทนที่จะเปิดไฟล์

**แยกงานซ่อมออกจากงานบาลานซ์เสมอ** — ตลอดเซสชันคงตัวเลขเดิมไว้ทุกตัวแม้จะเห็นว่าน่าจะผิด
เพื่อให้ตอนเล่นจริงแยกออกว่าอะไรเปลี่ยนเพราะซ่อม อะไรเปลี่ยนเพราะจูน

## 7 · ถ้าจะทำต่อ — เรียงตามคุ้ม

1. **กด Play** — ทุกอย่างด้านบนรอข้อนี้อยู่ · เริ่มจาก Orbiter (uptime พุ่ง) และ Splitter Bomb
   (fuse 1.2 วิ + ลูกย่อย 24 ลูกต่อการยิง)
2. **ลด `clusterPellets` ของ Splitter Bomb** — ค่า 8 ตั้งมาสำหรับกระสุนย่อย พอใช้เป็นจำนวน
   *ระเบิด* แล้ว 3 ลูกแม่ × 8 = 24 ระเบิดต่อการยิงหนึ่งครั้ง ลอง 3-4 ก่อน
3. **แยก prefab Blunderbuss** — โค้ดพร้อมแล้ว เหลืองาน Editor อย่างเดียว
4. **Orbiter orb กำพร้า** — ต้องมีคนเทสต์สองเครื่องยืนยันก่อนแก้
5. **raycast de-dup** — งานเดียวกับที่ทำกับ `OverlapEnemy` แค่คนละโครง
6. **โซนสายฟ้า tick แรก** — ย้าย `WaitForSeconds` ไปท้ายลูป
7. หนี้ที่เหลือใน ADR-007 (ข้อ 2, 4) และสตริง VFX ดิบ 7 จุดใน ADR-006 §6b
