## 3 · โค้ดที่แก้แล้วยังไม่ commit (15 ไฟล์)

### Netcode / lifecycle

**`GameTimeline` — ประตูเริ่มรัน**
เดิม `Update` นับเวลาตั้งแต่ `OnNetworkSpawn` ของตัวเอง ซึ่งเกิดก่อน player spawn
log จริง: `Wave 1` ที่ 22:58:52 → `LOSE t=00:04` ที่ 22:58:56 → `spawn player` ที่ 22:58:58
ตอนนี้ `hasStarted` (NetworkVariable) รอจนทุก client มี `PlayerObject`
ช่องใหม่ `waitForAllPlayers` (true) · `startWaitTimeout` (20s กันค้าง)

**`GameTimeline.CheckLoseCondition`** — เดิมเหมารวม "ยังไม่เกิด" กับ "ตายหมด" เป็นแพ้ทั้งคู่ · เพิ่มตัวนับ `spawned` เป็น 0 แล้ว return

**`WaveManager.WaveLoop`** — รอ `GameTimeline.hasStarted` ก่อนปล่อยเวฟ · เช็ค `Instance != null` ด้วยเพราะ `WeaponTestScene` ไม่มี GameTimeline

**`GameSessionManager` — จุดเกิดผู้เล่น**
เดิม `Instantiate(playerPrefab)` ไม่มี position ทุกคนจึงเกิดทับกัน
เพิ่ม `GetSpawnPosition(clientId)` + ช่อง `spawnPoints[]` · `spawnRingRadius` (2.5)
index มาจาก `PlayerSlotRegistry.GetSlot()` ตาม CLAUDE.md ข้อ 11 — log จริงมี client 0 กับ client 6 ถ้าใช้ `% 4` จะชนกัน

**`MenuManager.HandleJoined`** — เพิ่ม `SetMode(HubMode.Lobby)`
ร้าน Talent เป็นแท็บใน `lobbyPanel` ตัวเดียวกัน · เข้าร้านแล้ว join จะค้างโหมด Shop ไม่มีล็อบบี้
`OnPlayClicked` / `OnTalentShopClicked` ตั้งโหมดอยู่แล้ว มีแต่ `HandleJoined` ที่ลืม

**`playermove` — respawn ที่จุดที่ตาย**
`bool respawnAtSpawnPoint` → `enum RespawnPlace { DeathSpot, SpawnPoint, NextToTeammate }`
`DeathSpot` เป็นค่า 0 → prefab/scene ที่ยังไม่มีค่าจะได้ตัวนี้เอง
บันทึก `_deathPosition` ตอน `Die()` ไม่อ่าน `transform` ตอน respawn เพราะศพยังโดนกองศัตรูดันได้ระหว่างรอ
เพิ่ม `respawnInvulnSeconds` (2s) — โปรเจกต์นี้ไม่เคยมี i-frame ให้ player มาก่อน เกิดที่จุดที่ตายโดยไม่มีจะโดนตีซ้ำทันที

**`playermove.OnHealthChanged`** — vignette อ่าน `netMaxHealth` แทน field `maxHealth`
`GainMaxHealth` มี `if (!IsServer) return` ค่าบน client จึงค้างที่ `baseHealth` ตลอดรัน
เห็นได้จากบรรทัด debug บนหัวจอ: จอ client โชว์ `166/420 (local 120)` จอ host โชว์ `(local 420)`
ผลคือ vignette แรงเกินจริง 3.5 เท่าเฉพาะบนเครื่อง client

**`Enemy.OnNetworkSpawn`** — `rb.isKinematic = !IsServer`
เดิมตั้ง `false` ทุกเครื่อง physics ฝั่ง client จึงดันตัว enemy เองจนตำแหน่งเพี้ยน
เพิ่ม warning เมื่อ prefab ไม่มี `NetworkTransform`

### VFX

**`PlayerWeaponManager.SpawnLightningZonesServerSide`** — ย้าย `BroadcastVfxTypeClientRpc` ออกจากลูป damage tick
เดิม spawn VFX ใหม่ **ทุก tick ลงพิกัดเดิม** ทั้งที่ก้อนก่อนหน้ายังไม่หมดอายุ (TTL ~5.1s แต่ tick 0.3-1.0s)
Stormcaller 3 ก้อน → 1 · Molotov/Napalm 5 ก้อน → 1
เพิ่ม `vfxStartDelay` (default 0) และเตือนเมื่อ `explosionVfxKey == zoneVfxKey`

**`NetworkedVFXPool`** — เพิ่ม `GetVfxDuration(string)` + cache
`CalcTTL` รับ `includeInactive` เพิ่ม — prefab asset มี `activeInHierarchy = false` ทั้งก้อน ถ้าไม่ใส่จะได้ 0 particle แล้วตกไปใช้ค่าเดา `3f` เงียบๆ

### UI / Carousel

**`CharacterSelectUI` · `MapSelectUI`** — `rect.GetComponentInParent<T>(true)` แทน `host.GetComponent<T>()`
ซีนจริงเป็น `LeftPanel > Viewport > cardsContainer` และ component อยู่บน **LeftPanel** ห่างจากที่โค้ดหาชั้นเดียว
ของเดิมหาไม่เจอแล้ว `AddComponent` ตัวเปล่า reference ว่างทับ → ตัวที่ต่อสายไว้ไม่เคยถูก `Setup()`
**นี่คือคำตอบของ handoff 2026-08-22 §6 ข้อ 1** (`MapCarousel.previewImage` ทำงานครึ่งๆ)

**`CarouselBase`** — เลิกแปะ component ให้เอง
- ไม่ `AddComponent<RectMask2D>()` แล้ว เช็คแล้วเตือนแทน (ซีนมี `Mask` บน Viewport อยู่แล้ว)
- `fadeByDistance` (default **false**) — ปิดแล้ว script ไม่แตะ `CanvasGroup.alpha` และไม่แปะ `CanvasGroup` ให้การ์ด
- `ValidateOverlayGroup` — กัน `heroGroup`/`previewGroup` ชี้มาที่ container ของการ์ดเอง
- `ValidateOverlayImage` — กัน `heroImage`/`previewImage` ชี้ไป Image ใน **prefab asset**

**`CharacterCarousel` · `MapCarousel`** — เพิ่ม `heroIdleAlpha`/`heroMovingAlpha` และ `previewIdleAlpha`/`previewMovingAlpha`
default 1/0 = พฤติกรรมเดิม · ตั้ง moving = 1 เพื่อไม่ให้จางตอนลาก

**`CharacterSelectUI.RefreshDetail`** — portrait ตกกลับไปใช้ `icon` เมื่อ `portrait` ว่าง พร้อม warning
มีแค่ Riven ที่มี `portrait` · Hunter/Gunner ว่าง → `SetImage(null)` ปิด Image ทิ้ง ช่องเลยว่างเปล่า

### Analytics

**`AnalyticsManager`** — การต่อกับ UGS ปกติดี (`cloudProjectId` มี · `InitializeAsync` + `StartDataCollection` ถูกตาม API 6.x · เส้นทาง event ทั้ง 3 ตัวต่อครบ)
- `GetLocalCharacterName()` อ่านจาก `PlayerVisual.CharacterIndex` แทน `pwm.characterData` ซึ่งเป็น `{fileID: 0}` ใน prefab และไม่มีโค้ดไหนเขียน → ทุก event เป็น `character=Unknown` มาตลอด
- subscribe `OnLocalPlayerSpawned` **ก่อน** `await` — ของเดิมผูกหลัง init เสร็จ player ที่ spawn ระหว่างนั้นหลุดทั้งรัน
- เพิ่ม `Flush()` หลัง `game_session_end` (บัฟเฟอร์อัปโหลดทุก ~60s ปิดเกมก่อนก็หาย)
- ปลด subscription ของ player ตัวเก่าก่อนผูกตัวใหม่

**ยังต้องทำบน Unity Dashboard** — `RecordEvent` ไม่ throw เมื่อ schema ไม่ตรง log `Sent ...` จึงไม่ได้แปลว่าถึงเซิร์ฟเวอร์ ต้องประกาศ event + parameter ให้ครบทั้ง 3 ตัว

## 5 · บั๊กที่รู้แล้วยังไม่แก้

**`NetworkAnimator.m_Animator` ว่างบน `Purple 1.prefab`** — `NullReferenceException` **11,701 ครั้ง** ใน log เดียว (99% ของ error ทั้งไฟล์) เฟรมละครั้งตราบที่บอสยังอยู่
`Animator` อยู่บน GameObject เดียวกัน มี controller ครบ แค่ช่อง reference ว่าง

**non-host client เปลี่ยนแมพได้ในสายตาตัวเอง** — `LobbyState.SetMapServerRpc` ทิ้ง request ที่ไม่ใช่ host เงียบๆ (บรรทัด 172) แต่ `LobbyUI.SelectMap` เซ็ต `RunSetup` ฝั่ง client **ก่อน** ส่ง RPC และ `MapSelectUI` ไม่มีการเช็ค host เลย → client เห็นแมพเปลี่ยน แต่เข้าเกมได้แมพของ host

**การ์ด level up ว่างเปล่าได้** — `GetStatChanges` เทียบแค่ 5 จาก 8 ฟิลด์ (`radius` / `duration` / `piercing` ไม่เคยแสดง) ถ้าเลเวลอัปแล้วไม่มีฟิลด์ที่เทียบเปลี่ยน จะไม่มีทั้งคำอธิบายและแถวสเตตัส
`WD_GunnerPassiveWeapon` เข้าเงื่อนไขนี้ทั้ง 5 เลเวล (ยังยิงไม่โดนเพราะเข้าไม่ถึง card pool)
Molotov โตด้วย `radius` ทุกเลเวล (2.5 → 3.5) แต่**ไม่เคยแสดงบนการ์ดเลย**

**`ability` ยังไม่เคยเลเวลอัป** — `AbilityBase.SetLevel` ไม่มีผู้เรียก (ค้างจาก 2026-08-22)

**pool ยัง undersized** — `HitEffect 600/peak 891` · `Stormcaller_AOE 55/peak 463` · `MeteorAoE 65/peak 202`
**อย่าเพิ่งเอาตัวเลข "ควรตั้ง" ไปใส่** — ตัวเลขนั้นมาจาก peak ที่ยังนับก้อนซ้ำ ให้ Reset VFX Stats แล้ววัดใหม่หลังแก้ VFX
`MeteorAoE` เป็น entry เดียวใน 24 ตัวที่มี `Light` (pool 65 · peak 202) ตรงกับ log `visible additional lights exceeds maximum` 30 ครั้ง

**Bloom ไม่ clamp** — `SampleSceneProfile` มี `clamp` ที่ `m_OverrideState: 0` (= 65472) และ `PC_RPAsset.m_ColorGradingMode: 0` (LDR) → additive ที่ซ้อนกันเยอะกลายเป็นขาวแบนทั้งจอ

## 6 · งานออกแบบที่คุยไว้ (ยังไม่ลงมือ)

ค้นจาก LoL Swarm · Risk of Rain 2 · Vampire Survivors · HoloCure · Brotato · Halls of Torment · DRG Survivor · 20 Minutes Till Dawn · Bio Prototype

**ระบบที่คุ้มกว่าการเพิ่มอาวุธ**

1. **Overclock ที่ Lv3 / Lv5** (DRG กับ 20MTD คิดตรงกันโดยอิสระ) — เลือก 1 จาก 3 แทน "Lv4 ดาเมจ +9" · ได้ผลกับอาวุธ 51 ตัวพร้อมกัน และทำให้ `radius` / `duration` / `piercing` มีที่ใช้
2. **`scalesWith` / tag บน `WeaponData`** (LoL Swarm + Soulstone 27 skill types) — `AugmentData` ยังไม่มีอะไรให้เกาะ
3. **เพิ่มสูตร Fusion** (HoloCure) — ถูกกว่าเขียนอาวุธใหม่

**อาวุธที่ออกแบบไว้แล้ว** — ชุด AbilityHaste 6 ตัว (Overdrive Coil · Cadence Blade · Echo Blade · Chrono Mine · Cadence Siphon · Governor) และชุดจาก bullet-heaven 6 ตัว (Recall Bow · Salvo Marker · Wither · Deadman's Fuse · Kindling · Overpressure) พร้อมตาราง 5 เลเวล + Super
**ทุกตัวมีเพดานจำนวน object ชัดเจน** ตั้งใจตามบทเรียน pool limit ของ VS

สูตร haste ของโปรเจกต์คือ `100 / (100 + haste)` เป็น asymptote **ปลอดภัยกว่า VS ที่ตันแบบ −90%** ไม่ต้องใส่ cap เพิ่ม

**ช่องโหว่การออกแบบที่เจอ** — เงื่อนไขชนะคือฆ่า Main Boss ที่นาทีที่ 15 แต่อาวุธทั้ง 51 ตัวออกแบบมาเพื่อฝูงหมด ไม่มีตัวไหนที่ "ยิ่งศัตรูน้อยยิ่งแรง"
